9. Gestión de contacto y caso de teléfonos compartidos

No se crean campañas ni se envían mensajes. La plantilla operativa requiere autorización, canal y franja horaria, resultado, próxima acción y responsable. Cada persona conserva su propio identificador de beneficiario; un token local de grupo telefónico sirve solo para coordinar el calendario y nunca para fusionar personas. Antes de programar, el módulo comprueba restricciones de no contacto y gestiones pendientes; limita a una gestión por grupo telefónico y día y desplaza las demás a días posteriores.

La fuente no contiene preferencias y restricciones estructuradas suficientes. Deben confirmarse con la persona antes de usarlas. No se publica ni se exporta ningún teléfono.

10. Batch, uso y limitaciones

El batch opera sobre la plantilla transaccional futura porque las columnas actuales son agregados y no identifican operaciones del día anterior. Al recibir un CSV autorizado con fecha, recurso, monto y alias operativo, el comando filtra el día anterior a la fecha de corte y produce un reporte de logística agregado, sin teléfono ni cédula.

  1. Instalar Python 3.10+ (sin librerías externas).
  2. Ejecutar python pipeline.py --input "ruta\BD_F1380.xlsx".
  3. Abrir resultados\dashboard.html y resultados\informe_tecnico.html.
  4. Para el batch: python pipeline.py --batch "resultados\transacciones_template.csv" --cutoff YYYY-MM-DD.

Limitaciones: no hay transacciones de detalle, corte verificable, consentimiento, resultado de llamadas, catálogo completo de recursos, moneda confirmada ni datos suficientes para probar coordinación contra llamadas históricas. El prototipo no sustituye el sistema productivo ni la revisión jurídica y de seguridad.

11. Recomendaciones

  1. Definir un identificador de persona aleatorio y persistente separado del teléfono; conservar una relación identificadora solo en el sistema protegido.
  2. Capturar transacciones normalizadas (fecha, beneficiario, recurso, monto, estado, fuente) y mantener moneda y fecha de corte explícitas.
  3. Levantar consentimiento, restricciones, preferencias, canal y contacto pendiente con control de acceso.
  4. Validar montos, duplicados y códigos faltantes con el dueño de datos antes de corregir.
  5. Evaluar el modelo en periodos posteriores y por subgrupos antes de usarlo para priorización.
  6. Configurar respaldo cifrado, bitácora de ETL y retención; limitar accesos al Excel de origen.
